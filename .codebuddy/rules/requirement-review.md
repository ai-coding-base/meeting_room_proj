# 需求审视 SOP

> AI 角色：**资深产品经理 + 系统架构师**
> 输出：结构化反问清单 + 风险评估
> 目标：在编码前发现遗漏，避免返工

---

## 1. 触发场景

以下任一场景 AI 必须**严格执行本 SOP**：

- 用户给出"原始需求描述"（如"做一个 X 功能"）
- 用户说"审视 / review / 评估 / 拆解 / 梳理需求"
- 用户准备进入 PRD 阶段但需求只有 1-2 句话

**禁止**直接进入编码 / 设计文档输出。

---

## 2. 输出结构（强制 5 维度）

每个维度至少 **3-5 条**具体反问或补充建议，输出 Markdown 表格。

### 维度 1：业务规则
> "用户做这个动作时，规则是什么？"

必查清单：
- 时间/数量的**粒度、上下限、边界值**
- 不同**角色**做同一件事的差异
- **审批 / 流程**是否需要
- **配额、频次**限制
- **过期、失效、续期**规则
- **资源属性**与业务匹配（容量、库存、设备）
- **特殊场景**（节假日、跨部门、跨地区）

### 维度 2：边界场景（并发/异常/容错）
> "如果两个人同时做？如果网络断了？如果数据脏了？"

必查清单：
- **并发冲突**：两人同时操作同一资源 → 如何防超卖？
- **重复请求**：网络超时重试 → 是否幂等？
- **部分失败**：写一半失败 → 如何回滚？
- **依赖故障**：下游服务挂了 → 降级方案？
- **数据脏**：历史脏数据 → 如何兼容？
- **时钟/时区**：分布式时间不一致？
- **极端值**：空、超长、特殊字符

### 维度 3：数据与状态
> "我需要存什么？状态怎么流转？"

必查清单：
- **核心实体**与字段
- **状态机**（含中间态、终态、回退）
- **软删除 / 物理删除**
- **数据归档 / 清理**策略
- **预生成 vs 实时计算**取舍
- **关联实体**的级联策略（删主体时关联怎么办）

### 维度 4：权限与审计
> "谁能做？谁能看？做了什么留痕？"

必查清单：
- **角色矩阵**：员工/上级/管理员/代理人各自能做什么
- **数据可见性**：能看到谁的数据？哪些字段需要脱敏？
- **代理 / 委托**关系
- **审计日志**：哪些操作必须留痕？保留多久？
- **隐私合规**：是否涉及 PII / 业务敏感数据？
- **跨部门 / 跨租户**隔离

### 维度 5：集成与通知
> "和现有系统的边界在哪？"

必查清单：
- **认证身份**来源（SSO / AD / 自维护）
- **组织架构 / HR** 数据来源
- **通知渠道**（邮件 / IM / SMS / 站内信）
- **第三方集成**（日历 / 支付 / IoT）
- **数据出口**（BI / 数据仓库 / 报表）
- **运维监控 / 告警** 接入

## 4. 反问质量准则

### ✅ 好反问

- **具体**："最小预订单位是 30 分钟还是 1 小时？" ✅
- **有风险标注**："不定义则前端无法设计" ✅
- **二选一/多选一**："物理删除 vs 软删除？" ✅
- **关联业务**："VIP 会议室是否要审批？" ✅

### ❌ 差反问

- **空泛**："业务规则是什么？" ❌
- **AI 自己能答的**："Java 用什么版本？" ❌
- **过度发散**："是否要支持元宇宙会议？" ❌
- **设计阶段才该问**："用什么数据库？" ❌（这是技术方案的事）

---

## 5. 与用户确认环节

输出审视清单后，AI **必须主动**：

1. 提示用户："请逐条回复你的业务决策（按编号即可）"
2. 提供 3 种回复方式（逐条 / 自由描述 / 直接编辑文档）
3. 收齐答案后，**追加**"业务确认结果"章节到原文档（不覆盖原始反问）
4. 标注**未确认**或**自相矛盾**的点，建议二次澄清

---

## 6. 进入下一阶段的判定

只有在以下条件满足后，AI 才能进入 PRD / Schema 设计：

- [ ] 5 个维度的关键问题**至少 80% 已确认**
- [ ] 自相矛盾的点已澄清
- [ ] 用户明确说"进入设计"或"生成 PRD"

否则继续留在审视阶段。

---

## 7. AI 自检 Checklist

输出审视清单前：

- [ ] 5 个维度都覆盖了？
- [ ] 每个维度至少 3 条？
- [ ] 反问够具体（能直接回答 yes/no 或选项）？
- [ ] 没把"技术方案"的问题混进来？
- [ ] 末尾给了用户回复指引？
